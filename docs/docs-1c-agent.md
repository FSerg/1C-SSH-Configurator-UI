## 4.7. Работа конфигуратора в режиме агента

### 4.7.1. Общая информация

[cite\_start]Режим агента - специальный вариант пакетного режима запуска конфигуратора, в котором он (конфигуратор) выполняет функции SSH- и SFTP-сервера и принимает команды по этим протоколам[cite: 565]. [cite\_start]При работе в режиме агента, конфигуратор в один момент времени может работать только с одной информационной базой[cite: 566]. [cite\_start]Если нужно одновременно работать с несколькими информационными базами - необходимо запускать несколько конфигураторов в режиме агента[cite: 567].

Общая схема работы в режиме агента выглядит следующим образом:

1.  [cite\_start]Выполняется запуск конфигуратора в режиме агента[cite: 568].
2.  [cite\_start]С удаленного компьютера выполняется подключение к агенту[cite: 569].
3.  С помощью SFTP-клиента выполняется обмен файлами с агентом.
4.  [cite\_start]С помощью SSH-клиента выполняется передача команд агенту и получение результата работы[cite: 570].

[cite\_start]В режиме агента конфигуратор предоставляет определенный набор команд, который будет рассмотрен в данном разделе[cite: 571]. [cite\_start]Все команды исполняются интерактивно и синхронно[cite: 572]. [cite\_start]При выполнении команды не предоставляется возможность узнать состояние выполнения[cite: 572]. [cite\_start]Все сообщения, которые формируются после выполнения команд, полностью аналогичны таковым при выполнении аналогичных команд пакетного режима запуска конфигуратора[cite: 573].

[cite\_start]Результат работы команд в режиме агента могут быть представлены в двух форматах: в текстовом формате (по умолчанию) и в формате JSON-сообщений[cite: 574]. [cite\_start]При работе в формате JSON-сообщений, сервер всегда возвращает массив с информацией о результате работы[cite: 575]. [cite\_start]Для установки формата результата работы предназначена специальная команда[cite: 576]. [cite\_start]В конце обработки всех команд агент конфигуратора отправляет сообщение с типом success, error, cancel или question[cite: 576]. [cite\_start]Команда help отправляет в конце сообщение с типом success, а при вводе неизвестной команды - сообщение с типом error[cite: 577].

Для того чтобы запустить режим агента, следует выполнить команду следующего вида:

```
1cv8 DESIGNER <информационная база> /AgentMode [параметры режима агента] [/Visible].
```

[cite\_start][cite: 557]

При указании командной строки запуска следует учитывать следующие особенности:

  * [cite\_start]Для указания информационной базы может использоваться любой из доступных способов: параметры /IBName, /F или /S[cite: 582]. [cite\_start]При этом параметры, определяющие имя пользователя и пароль доступа к информационной базе, указывать не имеет смысла, эти параметры будут проигнорированы[cite: 583]. [cite\_start]Логин и пароль будет необходимо ввести в ответ на соответствующие запросы в консоли удаленного доступа[cite: 584]. [cite\_start]Также следует помнить, что для подключения к информационной базе, которая будет использоваться в режиме агента, не рекомендуется использовать пользователя, имя которого задано с использованием национальных символов[cite: 585].
  * В том случае, если в командной строке будет обнаружен параметр /AgentMode, конфигуратор будет игнорировать все параметры, кроме: параметров режима агента; параметров, указывающих информационную базу; [cite\_start]параметра /Visible[cite: 586, 587].
  * [cite\_start]Указание параметра /Visible приводит к появлению на экране специального окна, с помощью которого можно завершить работу режима агента[cite: 587]. [cite\_start]Если запуск выполняется без этого параметра, то завершить работу в режиме агента можно только с помощью командной строки удаленного доступа[cite: 588].

[cite\_start]К конфигуратору, работающему в режиме агента, может быть подключен один клиент по протоколу SSH и несколько клиентов по протоколу SFTP[cite: 589].

Смотри также:

  * [cite\_start]Описание работы с JSON (см. стр. см. здесь)[cite: 590].
  * [cite\_start]Команды работы в режиме агента (см. здесь)[cite: 591].

### 4.7.2. Список команд

В режиме агента предоставляются следующие команды:

  * [cite\_start]Команда help (подробнее см. здесь)[cite: 592].
  * [cite\_start]Группа команд common - общие команды (подробнее см. здесь)[cite: 593].
  * [cite\_start]Группа команд options - команды работы с настройками (подробнее см. здесь)[cite: 594].
  * [cite\_start]Группа команд config - команды редактирования конфигурации (подробнее см. здесь)[cite: 595].
  * [cite\_start]Группа команд infobase-tools - сервисные команды работы с информационной базой (подробнее см. здесь)[cite: 596].

Более подробное описание формата JSON-сообщений см. [cite\_start]здесь[cite: 597]. [cite\_start]В рамках данного раздела, все команды будут возвращать результат своей работы в текстовом формате[cite: 597]. [cite\_start]В качестве примера возврата в формате JSON-сообщений будет рассмотрен вывод команды help[cite: 598]. [cite\_start]Также следует понимать, что в формате JSON-сообщений будет выполняться возврат абсолютно всех команд агента, включая и команды получения справочной информации[cite: 599].

[cite\_start]Следует помнить, что все примеры, приведенные в данном разделе, не являются законченными конструкциями и предназначены только для демонстрации работы того или иного механизма или приема использования[cite: 600].

### 4.7.3. Команда help

[cite\_start]Данная команда предназначена для получения справочной информации[cite: 601]. [cite\_start]Команда help без параметров покажет общую информацию по использованию режима агента[cite: 601].

```
designer> help
Использование:
 help [options] [arguments]
Общие параметры:
 --version | -v  получение версии утилиты
Режим:
 help (h)
 Отображение справочной информации для указанного режима.
Аргументы:
 MODE
 режим, для которого необходимо получить информацию о ключах командной строки
Поддерживаемые режимы:
 help Отображение справочной информации для указанного режима.
 common Общие команды
 options Управление настройками
 config Режим работы с конфигурацией
 infobase-tools Сервисные функции работы с информационной базой
designer>
```

[cite\_start][cite: 579, 580, 581, 582]

[cite\_start]Если требуется получить более конкретную информацию о группе команд или какой-то конкретной команде, то следует всю эту информацию ввести после ключевого слова help[cite: 604]. [cite\_start]Например, для получения информации о группе команд options необходимо выполнить команду `help options`[cite: 605].

```
designer> help options
Использование:
 options [command] [options]
Общие параметры:
 --version | -v  получение версии утилиты
Режим:
 options
 Управление настройками
Команды:
 list
 Вывести значения всех настроек
 get
 Получить значение настройки
 --output-format
 Формат вывода
 --show-prompt
 Показывать приглашение командной строки
 set
 Установить значение настройки
 --output-format=<text|json>
 Формат вывода
 --show-prompt=<yes|no>
 Показывать приглашение командной строки
designer>
```

[cite\_start][cite: 602, 603]

[cite\_start]Для получения версии системы «1С:Предприятие», которая выполняется в режиме агента, необходимо выполнить команду `help –version`[cite: 606].

```
designer> help --version
8.3.10.2000
designer>
```

[cite\_start][cite: 606]

[cite\_start]Если установить формат вывода в JSON-сообщения, то вывод информации о версии платформы «1С:Предприятие» будет выглядеть следующим образом[cite: 607]:

```
designer> options set --output-format=json
[
 {
 "type": "success",
 "message": ""
 }
]
designer> help --version
[
 {
 "type": "success",
 "body": "8.3.10.1772"
 }
]
designer>
```

[cite\_start][cite: 607]
[cite\_start]В данном примере первая команда (options set …) устанавливает формат вывода, а следующая команда получает версию системы «1С:Предприятие»[cite: 607].

### 4.7.4. Команды группы common

[cite\_start]Команды группы common отвечают за общие операции[cite: 608]. В состав группы входят следующие команды:

  * [cite\_start]`connect-ib` - выполнить подключение к информационной базе, параметры которой указаны при старте режима агента[cite: 608].
  * [cite\_start]`disconnect-ib` - выполнить отключение от информационной базы, подключение к которой ранее выполнялось с помощью команды connect-ib[cite: 609].
  * [cite\_start]`shutdown` - завершить работу конфигуратора в режиме агента[cite: 610].

[cite\_start]Команды данной группы не имеют параметров[cite: 610].

### 4.7.5. Команды группы options

#### 4.7.5.1. Назначение группы команд

[cite\_start]Команды группы options отвечают за управление настройкам текущей сессии[cite: 611]. [cite\_start]В состав группы входят следующие команды[cite: 612]:

#### 4.7.5.2. get

[cite\_start]Данная команда позволяет получить значения параметров[cite: 613]. Для команды доступны следующие параметры:

  * [cite\_start]`--output-format` - позволяет указать формат вывода результата работы команд[cite: 614]:
      * [cite\_start]`text` - команды возвращают результат в текстовом формате[cite: 614].
      * [cite\_start]`json` - команды возвращают результат в формате JSON-сообщений[cite: 615].
  * [cite\_start]`--show-prompt` - позволяет управлять наличием приглашения командной строки designer\>[cite: 616]:
      * [cite\_start]`yes` - в командной строке есть приглашение[cite: 616];
      * [cite\_start]`no` - в командной строке нет приглашения[cite: 617].
  * [cite\_start]`--notify-progress` - позволяет получить информацию об отображении прогресса выполнения команды[cite: 618].
  * [cite\_start]`--notify-progress-interval` - позволяет получить интервал времени, через который обновляется информация о прогрессе[cite: 619].

#### 4.7.5.3. list

[cite\_start]C помощью данной команды можно просмотреть список параметров и их (параметров) текущее состояние[cite: 620].

#### 4.7.5.4. set

[cite\_start]Данная команда позволяет выполнить установку значений параметров[cite: 621]. Для команды доступны следующие параметры:

  * [cite\_start]`--output-format` - позволяет указать формат вывода результата работы команд[cite: 621]:
      * [cite\_start]`text` - команды возвращают результат в текстовом формате[cite: 621].
      * [cite\_start]`json` - команды возвращают результат в формате JSON-сообщений[cite: 622].
  * [cite\_start]`--show-prompt` - позволяет управлять наличием приглашения командной строки designer\>[cite: 623]:
      * [cite\_start]`yes` - в командной строке есть приглашение[cite: 623];
      * [cite\_start]`no` - в командной строке нет приглашения[cite: 624].
  * [cite\_start]`--notify-progress` - позволяет управлять выводом информации о прогрессе выполнения команды[cite: 625]:
      * [cite\_start]`yes` - отображается прогресс[cite: 625];
      * [cite\_start]`no` - прогресс не отображается (значение по умолчанию)[cite: 626].
  * [cite\_start]`--notify-progress-interval` - позволяет указать интервал времени, через который обновляется информация о прогрессе[cite: 627]. [cite\_start]Значение задается с точностью 0.1 секунды[cite: 628]. [cite\_start]Значение по умолчанию равно 1 секунда[cite: 628]. [cite\_start]Нарушение точности приводит к формированию ошибки CommandLineFormaError[cite: 629].

### 4.7.6. Команды группы config

#### 4.7.6.1. Назначение группы команд

[cite\_start]Команды группы config отвечают за команды редактирования конфигурации[cite: 630].

#### 4.7.6.2. dump-cfg

[cite\_start]Команда позволяет выполнить выгрузку конфигурации или расширения в файл[cite: 630]. Для команды доступны следующие параметры:

  * [cite\_start]`--file <путь>` - путь к файлу конфигурации (cf-файл) или расширению (cfe-файл)[cite: 631].
  * [cite\_start]`--extension <имя расширения>` - содержит имя расширения, которое будет выгружено в файл[cite: 632].

#### 4.7.6.3. dump-config-to-files

[cite\_start]Команда позволяет выполнить выгрузку конфигурации в xml-файлы[cite: 633]. Для команды доступны следующие параметры:

  * [cite\_start]`--dir <путь>` - содержит путь к каталогу, в который будет выгружена конфигурация[cite: 633]. [cite\_start]Параметр является обязательным[cite: 634].
  * [cite\_start]`--extension <имя расширения>` - содержит имя расширения, которое будет выгружено в файлы[cite: 634].
  * [cite\_start]`--all-extensions` - если параметр указан, то в файлы будут выгружены все расширения конфигурации[cite: 635].
  * `--format [hierarchical|plain]` - определяет формат выгрузки. [cite\_start]По умолчанию используется иерархический формат выгрузки (hierarchical)[cite: 636].
  * [cite\_start]`--update` - обновить существующую выгрузку[cite: 637]. [cite\_start]В этом случае будут выгружены только те объекты, версии которых отличаются от версий, указанных в файле ConfigDumpInfo.xml[cite: 637].
  * [cite\_start]`--force` - выполнить полную выгрузку, если при попытке обновления выгрузки (параметр update) выяснилось, что текущая версия формата выгрузки не совпадает с версией формата выгрузки, которая указана в файле ConfigDumpInfo.xml[cite: 638].
  * [cite\_start]`--get-changes <путь>` - сформировать файл, который содержит изменения между текущей и указанной выгрузками конфигурации[cite: 639].
  * [cite\_start]`--config-dump-info-for-changes <путь>` - путь к файлу ConfigDumpInfo.xml, который используется для формирования файла изменений между двумя выгрузками конфигурации[cite: 640].
  * [cite\_start]`--list-file <файл>` - выгрузить только объекты метаданных и/или внешние свойства, указанные в файле, вне зависимости от того были они изменены или нет[cite: 641].
  * [cite\_start]`--server` - указывает на необходимость выполнить выгрузку конфигурации в файлы на стороне сервера «1С:Предприятия»[cite: 642]. [cite\_start]В этом случае выгрузка будет выполняться в многопоточном режиме (и будет выполняться быстрее)[cite: 643]. [cite\_start]Для указания количества используемых потоков используется параметр --threads[cite: 644].
  * [cite\_start]`--threads=<количество>` - позволяет указать, какое количество одновременно работающих фоновых заданий будет использоваться для выгрузки конфигурации в файлы на стороне сервера[cite: 645]. [cite\_start]Применимо только одновременно с командой --server[cite: 646].
  * [cite\_start]`--archive=<имя файла>` - позволяет выполнить выгрузку конфигурации в файл zip-архива[cite: 648].
  * `--ignore-unresolved-refs` - в выгрузке конфигурации не выгружаются ссылки к недостижимым объектам, т. е. [cite\_start]к таким объектам, которые были удалены в одной из предыдущих версий конфигурации[cite: 650, 651].

#### 4.7.6.4. dump-external-data-processor-or-report-to-files

[cite\_start]Команда позволяет выполнить выгрузку внешних обработок или отчетов в xml-файлы[cite: 652]. Для команды доступны следующие параметры:

  * [cite\_start]`--file <файл>` - содержит имя файла, который будет выступать в роли корневого файла выгрузки внешней обработки/отчета в формате XML[cite: 653]. [cite\_start]Параметр является обязательным[cite: 654].
  * [cite\_start]`--ext-file <файл>` - полное имя файла с выгружаемой внешней обработкой (*.epf) или отчетом (*.erf)[cite: 654].
  * [cite\_start]`--format [hierarchical|plain]` - определяет формат выгрузки[cite: 655]. [cite\_start]По умолчанию используется иерархический формат выгрузки (hierarchical)[cite: 656].

#### 4.7.6.5. generation-id

[cite\_start]Команда позволяет получить идентификатор текущего «поколения» метаданных конфигурации[cite: 656]. Для команды доступны следующие параметры:

  * [cite\_start]`–-extension` - выполняется получение идентификатора метаданных указанного расширения[cite: 657]. [cite\_start]Если параметр не указан - идентификатор получается для основной конфигурации[cite: 658].

#### 4.7.6.6. load-cfg

[cite\_start]Команда позволяет выполнить загрузку конфигурации или расширения из файла[cite: 658]. Для команды доступны следующие параметры:

  * [cite\_start]`--file <путь>` - путь к файлу конфигурации (cf-файл) или расширению (cfe-файл)[cite: 659].
  * [cite\_start]`--extension <имя расширения>` - содержит имя расширения, которое будет загружено из файла[cite: 660].

#### 4.7.6.7. load-config-from-files

[cite\_start]Команда позволяет выполнить загрузку конфигурации из XML-файлов[cite: 661]. Для команды доступны следующие параметры:

  * [cite\_start]`--dir <путь>` - содержит путь к каталогу, из которого будет загружена конфигурация[cite: 661]. [cite\_start]Параметр является обязательным[cite: 662].
  * [cite\_start]`--extension <имя расширения>` - содержит имя расширения, которое будет загружено из файлов[cite: 662].
  * [cite\_start]`--all-extensions` - если параметр указан, то из файлов будут загружены все расширения конфигурации[cite: 663].
  * `--format [hierarchical|plain]` - определяет формат выгрузки. [cite\_start]По умолчанию используется иерархический формат выгрузки (hierarchical)[cite: 664].
  * [cite\_start]`--files <файл[, файл]>` - список файлов, которые требуется загрузить[cite: 665]. [cite\_start]Файла разделяются запятыми[cite: 665].
  * [cite\_start]`--list-file <файл>` - путь к файлу, в котором перечислены загружаемые файлы[cite: 667].
  * [cite\_start]`--update-config-dump-info` - после окончания загрузки создать в директории файл ConfigDumpInfo.xml, соответствующий загруженной конфигурации[cite: 669].

  * [cite\_start]`--dynamic-enable` - сначала выполняется попытка динамического обновления, если она завершена неудачно, будет запущено фоновое обновление[cite: 704].

  * [cite\_start]`--warnings-as-errors` - при указании данного параметра все предупреждения, которые могут возникнуть при обновлении конфигурации базы данных, будут считаться ошибками[cite: 706].
  * [cite\_start]`--background-start` - при указании данного параметра будет запущено фоновое обновление конфигурации, а текущий сеанс будет завершен[cite: 707].
  * [cite\_start]`--background-cancel` - при указании данного параметра происходит отмена запущенного фонового обновления конфигурации базы данных[cite: 708].
  * [cite\_start]`--background-finish` - при указании данного параметра запущенное фоновое обновление конфигурации базы данных будет завершено[cite: 709].
  * [cite\_start]`--background-resume` - при указании данного параметра система продолжает фоновое обновление конфигурации базы данных, приостановленное ранее[cite: 711].
  * [cite\_start]`--server` - данный параметр указывает, что обновление конфигурации базы данных необходимо выполнить на стороне сервер «1С:Предприятия»[cite: 712].
  * [cite\_start]`--extension <имя расширения>` - имя расширения[cite: 713].
  * [cite\_start]`--session-terminate <назначение>` - завершение активных сеансов в случае необходимости установки эксклюзивной блокировки информационной базы[cite: 714].

### 4.7.8. Формат JSON-сообщений

[cite\_start]В том случае, если установлен формат вывода в виде JSON-сообщений, сервер всегда будет возвращать массив из различной комбинации следующих значений[cite: 770]:

  * [cite\_start]**Имя: type**, обязательное[cite: 770].
      * [cite\_start]**Возможные значения:** `log | success | error | canceled | question | dbstru | loading-issue | progress | extension-info`[cite: 771, 772].
      * **Описывает тип сообщения:**
          * [cite\_start]`log` - информационное сообщение[cite: 773].
          * [cite\_start]`success` - операция успешно завершена[cite: 773].
          * [cite\_start]`error` - операция завершена с ошибкой[cite: 774].
          * [cite\_start]`canceled` - операция отменена[cite: 774].
          * [cite\_start]`question` - вопрос пользователю[cite: 775].
          * [cite\_start]`dbstru` - информация о процессе реструктуризации[cite: 775].
          * [cite\_start]`loading-issue` - ошибки и предупреждения, накопленные за время загрузки конфигурации из файлов[cite: 776].
          * [cite\_start]`progress` - информация о прогрессе выполнения команды[cite: 777].
          * [cite\_start]`extension-info` - информация о расширении, которое находится в информационной базе[cite: 778].
  * **Имя: error-type**
      * [cite\_start]Содержит тип ошибки, которая возникла при выполнении команды[cite: 780]:
          * [cite\_start]`UnknownError` - неизвестная ошибка[cite: 780].
          * [cite\_start]`DesignerNotConnectedToInfoBase` - соединение с информационной базой не установлено[cite: 781].
          * [cite\_start]`DesignerAlreadyConnectedToInfoBase` - соединение с информационной базой уже установлено[cite: 782].
          * [cite\_start]`CommandFormatError` - неверный формат команды[cite: 782].
          * [cite\_start]`DBRestructInfo` - ошибка реструктуризации базы данных[cite: 783].
          * [cite\_start]`InfoBaseNotFound` - информационная база не найдена[cite: 783].
          * [cite\_start]`AdministrationAccessRightRequired` - для выполнения операции требуются административные права[cite: 784].
          * [cite\_start]`ConfigFilesError` - ошибки в процессе загрузки/выгрузки конфигурации из/в файла[cite: 785].
          * [cite\_start]`DesignerAlreadyStarted` - обнаружен запущенный конфигуратор[cite: 785].
          * [cite\_start]`InfoBaseExclusiveLockRequired` - требуется исключительная блокировка информационной базы[cite: 786].
          * [cite\_start]`LanguageNotFound` - язык не обнаружен[cite: 786].
          * [cite\_start]`ExtensionWithDataIsActive` - расширение конфигурации активно и содержит данные[cite: 787].
          * [cite\_start]`ExtensionNotFound` - расширение не обнаружено[cite: 787].
  * **Имя: message**
      * [cite\_start]Содержит локализованное сообщение об ошибке[cite: 789].
  * **Имя: body**
      * [cite\_start]Содержание данного значения зависит от конкретной операции[cite: 790].
