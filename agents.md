# Руководство для LLM-агентов по проекту 1C Agent UI

Назначение: дать LLM‑агентам понятные и практичные правила, как безопасно и последовательно развивать этот репозиторий.

Область действия: весь репозиторий.

---

## Обзор проекта

- Приложение: Streamlit‑UI для управления удалённым Агентом Конфигуратора 1С по SSH.
- Основные действия: выгрузка/загрузка конфигурации, расширений, внешних отчётов/обработок (EPF/ERF) в файлы и обратно; служебные команды (`help --version`, `update-db-cfg`, `dump-ib`/`restore-ib`).
- Хранение: локальный JSON‑файл `~/.1c-agent-ui/projects.json` с лёгкой обфускацией секретов.
- Запуск: локально (`streamlit run streamlit_app.py`) или через Docker/Compose.

Ключевые модули
- `streamlit_app.py` — точка входа; вызывает `app.ui.run_app()`.
- `app/ui.py` — Streamlit‑интерфейс, постановка операций в очередь, отображение логов, сборщики последовательностей команд.
- `app/agent_client.py` — высокоуровневый клиент поверх SSH‑канала; потоковый парсер JSON‑сообщений от агента.
- `app/ssh.py` — менеджер подключений Paramiko, управление shell‑каналом.
- `app/models.py` — модели Pydantic (v1.x): креды, проект, опции запуска, сообщения.
- `app/storage.py` — JSON‑хранилище проектов с обфускацией (через `app.utils`).
- `app/utils.py` — обфускация секретов, нормализация путей, хелперы списков.
- `tests/test_core.py` — unittest‑покрытие утилит и хранилища.

Документация и запуск
- `README.md` — запуск локально и в контейнере.
- `docs/docs-1c-agent.md` — справка по командам/опциям 1C‑агента.

## Запуск, сборка, тесты

Локально
- `python -m venv venv && source venv/bin/activate`
- `pip install -r requirements.txt`
- `streamlit run streamlit_app.py`
- Необязательная переменная: `ONEC_AGENT_UI_SECRET_SALT` для своей соли обфускации.

Docker
- `docker build -t 1c-agent-ui .`
- `docker run --rm -p 8501:8501 -v 1c-agent-ui:/root/.1c-agent-ui 1c-agent-ui`

Docker Compose
- `docker compose up -d --build` (по compose проброшено `8502:8501`).

Тесты
- Встроенный unittest: `python -m unittest -v`
- Новые тесты добавляйте в `tests/`, ориентируясь на `tests/test_core.py`.

## Стиль кода и соглашения

Общее
- Python 3.11+; используйте аннотации типов. Минимизируйте зависимости, опирайтесь на стандартную библиотеку.
- Docstring’и и комментарии — на английском. Тексты UI — на русском (как сейчас).
- Функции — компактные и связные; общие хелперы — в `utils.py`.

Pydantic (v1.x)
- Используйте `BaseModel`, `Field`, `validator`. Для сериализации — `.model_dump(mode="json")` если доступно, иначе `.json()` (пример в `storage.py`).
- Не обновляйте на Pydantic v2 без полной адаптации репозитория.

Секреты и хранилище
- Никогда не логируйте пароли/пасфразы в открытом виде. Применяйте `obfuscate_secret`, `reveal_secret`, `mask_secret` из `app.utils`.
- Путь к хранилищу: `~/.1c-agent-ui/projects.json` (`DEFAULT_STORAGE_PATH`); создавайте родительский каталог.

Пути для агента
- Все удалённые пути — только относительные от базового каталога агента и начинаются с `../`. Валидация в `normalize_relative_agent_path`.

SSH/Агент
- Только `SSHConnectionManager` (Paramiko) и `AgentClient` — не используйте внешние процессы/subprocess.
- Держите инициализацию сессии в `AgentClient._initialize_session()` (JSON‑формат, прогресс, без приглашения).
- Соблюдайте контракт `_JsonArrayParser`: парсинг верхнеуровневых JSON‑массивов, которые стримит агент.

Состояние Streamlit
- Используются ключи: `selected_project_uid`, `project_form_data`, `operation_in_progress`, `pending_operation`, `project_flash`, `last_operation_result`.
- Операции ставятся в очередь `_queue_operation(...)`, фактический запуск — через `_maybe_execute_pending_operation(...)` в выбранной вкладке.

## Как добавить новую операцию

1) Сборщик последовательности в `app/ui.py`
- Ориентируйтесь на `_build_dump_config_sequence`, `_build_load_config_sequence` и др.
- Команды формируйте строками, которые принимает 1C‑агент. Для путей — `self._join_remote(base, name)`.
- Для действий с конфигурацией используйте `_build_config_command(...)` — он корректно применяет флаги из `RunOptionsModel`.

2) Включение в вкладку
- Добавьте кнопку в нужной вкладке (`_render_configuration_tab`, `_render_extensions_tab`, `_render_externals_tab`, `_render_tools_tab`).
- Вызывайте `_queue_operation(project, title, commands, scope=...)` с осмысленным заголовком и скоупом.
- Запрещайте параллельные операции: проверяйте `_is_operation_running()` при активации кнопок.

3) Логи единообразно
- Используйте прогресс‑колбэк из `AgentClient.execute_sequence`, формируйте строки через `_format_log_entry`.

4) Тесты
- Для чистых хелперов (строки, пути) добавляйте unit‑тесты в `tests/`.
- Сетевые части не покрываем интеграционно; тестируйте билдеры и утилиты.

## Что делать / чего не делать

Делать
- Сохранять единый стиль русскоязычных UI‑текстов и краткие сообщения пользователю.
- Сохранять JSON‑стрим и сообщения прогресса от агента.
- Валидировать/нормализовать удалённые пути, санитизировать пользовательский ввод.
- Держать Docker‑образ минимальным; при необходимости системных зависимостей — расширять `Dockerfile` точечно.

Не делать
- Не логировать и не хранить секреты в открытом виде.
- Не вызывать внешние утилиты для общения с агентом — только Paramiko‑канал.
- Не ломать формат хранилища обратно несовместимо; при необходимости — миграция в `ProjectStorage`.
- Не блокировать UI долгими паузами; используйте короткий polling как сейчас.

## Архитектурные заметки

- Один SSH‑shell‑канал на сессию; баннер читается один раз; при необходимости — реинициализация.
- Финальные типы сообщений от агента: `success`, `error`, `cancel`. Таймаут выполнения на команду настраивается.
- Жизненный цикл операции: очередь → выполнение (с опциональными connect/disconnect) → стрим логов → завершение → статус в сайдбаре.

## Идеи для развития (опционально)

- UX: экспорт/импорт проектов, подтверждения действий, улучшенные сообщения об ошибках из агента.
- Функции: предварительный просмотр пакетных операций, dry‑run, выборки из списков, пресеты.
- Надёжность: ретраи/бэкофф на временные SSH‑сбои, тонкая настройка keepalive.
- Тесты: покрыть `_JsonArrayParser`, билдеры команд и хелперы путей.
- Безопасность: опционально системный keychain для секретов; усиленная обфускация при необходимости.

## Чек‑листы

Правки UI
- Русские лейблы, без утечек секретов, сохранение ключей состояния.
- Поток: `_queue_operation` → `_maybe_execute_pending_operation`.

Правки хранилища
- Обфускация чувствительных полей при сохранении, деобфускация при загрузке.
- Стабильность UID; обновление меток времени через `ProjectModel.touch()`.

Расширение команд агента
- Инициализируйте сессию, если требуются новые режимы вывода.
- Соблюдайте синтаксис 1C‑агента из `docs/docs-1c-agent.md`.
